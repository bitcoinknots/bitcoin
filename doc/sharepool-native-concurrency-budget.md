# Native concurrency and optional decoded-retention budget

The native validation service now shares a **128 MiB optional decoded-retention budget** across its per-invocation LRUs. This is not a whole-process memory or fairness limit. The earlier native preparation experiments predate this cap; their [capture manifest](../contrib/sharepool/results/production-native-preparation-verification.json) and [reconstructable source patch](../contrib/sharepool/results/production-native-preparation-source.diff) identify that earlier source selection.

## Current concurrency

| Route | Concurrency and relevant code |
|---|---|
| HTTP RPC | Defaults to **16 executing worker threads** and **64 queued requests**, both configurable. [Defaults](../src/httpserver.h#L18), [worker creation](../src/httpserver.cpp#L607), [bounded FIFO](../src/httpserver.cpp#L75). |
| RPC batches | Each batch runs its requests sequentially on one HTTP worker; it does not create another validation thread. [Batch loop](../src/httprpc.cpp#L241). |
| Pending block retry | One dedicated worker, processing its bounded pending-block list sequentially. Requests coalesce into a flag. [Worker](../src/sharepool/retry_worker.h#L37), [retry loop](../src/validation.cpp#L5803). |
| GUI or embedding | `Node::executeRpc` calls the RPC table directly, bypassing the HTTP worker ceiling. The Qt console has its own executor thread. There is no universal native-call admission semaphore. [Direct route](../src/node/interfaces.cpp#L359), [Qt executor](../src/qt/rpcconsole.cpp#L1323). |
| P2P admission | One message-processing critical section serializes this route. Four snapshot-download reservations bound raw transfer bytes to 64 MiB. Admission decoding runs outside `cs_main`, but still holds `g_msgproc_mutex`. [Limits](../src/net_processing.cpp#L239), [admission](../src/net_processing.cpp#L4043). |

Job preparation/finalization, template checks and proof checks reach the per-invocation decoded LRU through [the mining RPCs](../src/rpc/mining.cpp#L1915) and [native validation](../src/validation.cpp#L5560). Each LRU still permits **64 MiB of charged retention and 1,024 entries**. Previously, the ordinary `bitcoind` HTTP plus retry routing had a sum of `(16 + 1) × 64 MiB = 1,088 MiB` in optional-cache ceilings. Now every LRU receives the same ChainstateManager-owned budget, so their aggregate charged retention is at most **128 MiB**, including direct RPC/embedding calls and retry work regardless of HTTP worker count. These figures are accounting ceilings, not measured usage or process RSS bounds.

Other allocations are separate. [TIDES history](../src/consensus/sharepool_hash.cpp#L1562) has a persistent thread-local index with default **64 MiB delta and 64 MiB query budgets per participating thread** ([configuration](../src/sharepool/tides_history.h#L65)). HTTP request/JSON bodies, raw snapshot storage, checker-owned dependency references and derived state, script preparation, transaction caches and allocator overhead are additional. The regtest SharePool HTTP body limit is 48 MiB per request; the queue bounds request count, not aggregate process bytes ([HTTP setup](../src/httpserver.cpp#L575)).

## Implemented optional-cache budget

[DecodedSnapshotRetentionBudget](../src/sharepool/hash_validation_cache.h) uses a checked atomic counter and move-only leases. The [validation service](../src/validation.h) owns one immutable budget shared by job preparation, historical-template checks and proof checks. The 128 MiB default is local policy; it introduces no configuration argument, consensus rule or wire field.

At insertion, an overflow-checked atomic reservation either acquires capacity or declines retention when capacity is exhausted; it never waits for another entry to be freed. A move-only lease belongs to the LRU entry and releases its reservation on replacement, eviction, allocation failure or destruction. Atomic bookkeeping performs no decoding, disk I/O, callbacks or native validation and takes no chain lock. A denied reservation means “do not retain this value”: [the lookup still returns the newly decoded available snapshot](../src/validation.cpp#L5416). Optional retention allocation failures also decline retention. Neither case becomes missing data or skips authentication. Leases keep their accounting state alive independently of the service owner.

This controls optional retention only. The verifier can still own a decoded object after its LRU entry is evicted; freshly decoding a value also allocates before retention is considered. Charging until the last shared owner releases it would measure a different, larger resource. Enforcing a hard total-live-allocation ceiling would additionally require scheduling/admission and bounded scratch space, not silently suppressing available evidence. TIDES history cursors need a separate design: indiscriminate eviction can discard resumable progress through long history.

## Fairness and required tests

The optional-cache cap alone will not reserve CPU time or low-latency RPC service. All HTTP workers can execute heavy calls, and the FIFO has no per-client or per-method quota. [Native body preparation](../src/validation.cpp#L5439) still reads blocks/undo data and captures coins/script context under `cs_main`; snapshot/index writes also retain that lock. Existing peer turns and retry backoff do not schedule HTTP callers. A separate proposal should reserve validation service for required block dependencies and keep short status calls responsive, with cancellation and tip-context rechecks.

The final **61-case focused native suite passed**, including the four new budget/equivalence cases. The [final source, binary and test manifest](../contrib/sharepool/results/production-native-shared-budget-verification.json) records this source selection separately from the earlier benchmarks. Verification is separated from remaining service-wide tests:

1. Added accounting tests: caches share a tiny budget: different entries, duplicate immutable objects, replacement, local eviction, zero/oversized budgets and destruction all preserve the aggregate ceiling. Conservative duplicate charging is acceptable.
2. Added eight-thread synchronized insert/evict/destruct loops check the aggregate ceiling and final zero charge. Lease tests cover overflow at `SIZE_MAX`, move assignment, exception unwinding after reservation, and accounting lifetime beyond the service owner. The standalone [fault/stress harness](../contrib/sharepool/results/production-native-shared-budget-stress.cpp) also passed eight threads × 10,000 insert/evict attempts under ThreadSanitizer and without instrumentation. Its isolated allocator override faults actual `Put`/map insertion after verifying the reservation is held, then checks zero leaked charge and usable caller evidence. No production allocator hook was added. [Captured compiler/run results](../contrib/sharepool/results/production-native-shared-budget-stress.json).
3. Added compact-v7 full block, mining-job, historical-template and proof validation fixtures with ample, one-record, one-byte and zero shared retention. They compare full results for valid evidence, wrong payouts, invalid owner/proof signatures, malformed evidence and missing ancestry; available uncached values remain usable. Existing dependency-work limits are unchanged and remain covered by the full focused suite.
4. Reorg/change-tip and cancellation fences remain unchanged; simultaneous contention at those boundaries still needs a dedicated integration test. A later invocation still obtains evidence through the store again, which may itself retain authenticated raw bytes. There is no shared decoded-object cache or verdict cache.
5. Saturate the configured RPC workers alongside pending-block retry and P2P admission. Record admitted work, backlog, process RSS, cache counters, per-route queue delay, short-RPC p95/p99, and `cs_main` wait/hold time. Repeat with slow storage and unavailable evidence. No latency threshold is established by the optional-memory cap itself.

## What was actually measured

The finite **30-miner, 270-proof, seven-block** comparison passed payouts and peer recovery. Node 0 CPU changed from **38.17 to 33.19 seconds**; its sampled peak RSS was approximately **70.8 to 70.9 MB**. The [before](../contrib/sharepool/results/production-native-preparation-before.json) and [after](../contrib/sharepool/results/production-native-preparation-after.json) reports contain the full observations. This did not saturate all 16 RPC workers. One baseline CPU-sampling interval and uncontrolled host load also limit the timing comparison.

The subsequent original **100-miner/900-proof** repeat was slower overall, so the small comparison does not establish a production speedup. An isolated, warmed **A/B/A** replay used 100 retained real template/proof pairs with and without only the two new historical/proof LRUs: wall times were **24.252, 24.107 and 23.840 seconds**. The disabled arm was 0.25% slower than the mean enabled arms, within their 1.70% drift. All 200 complete response objects and invalid-signature/missing-data controls matched. This supports retaining the current behavior without attributing the larger-run slowdown to optional retention; it does not measure the new shared cap. [Exact replay and restoration evidence](../contrib/sharepool/results/production-native-retention-ab-verification.json).

The shared optional-cache cap is implemented, but all-worker saturation, a whole-process RSS ceiling, cold/slow-disk lock measurements and a starvation bound remain unproven. Current [retry duration counters](../src/rpc/mining.cpp#L2148) measure complete passes, not time spent holding `cs_main`.
