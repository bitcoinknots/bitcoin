Long coinbase maturity: one year, released with RDTS
----------------------------------------------------

The temporary softfork that Bitcoin Knots 29.4.2 deployed to hold generated bitcoins for longer is extended: instead of ending at block 979920, it ends when RDTS expires. Bitcoins generated by block 973440 or any later block cannot be spent in any block whose parent has a median time past earlier than 2027 September 1st 00:00 UTC. From the first block past that, they are spendable at the ordinary maturity of 100 blocks.

This is a softfork on top of 29.4.2. Up to block 979919 the rules are the same, so nothing changes until then. Block 979920 is the first that 29.4.2 could accept and this version reject (one spending bitcoins generated since block 973440), so miners and nodes need to upgrade before it, expected between the 17th and the 24th of October.

A node that upgrades only after block 979920 rechecks the blocks it connected from that height on at its first start. This needs their block and undo data: a pruned node that upgrades late may have to reindex, and any node that upgrades late rewinds and reconnects everything since block 979919. Upgrading before block 979920 avoids both.

Policy and the wallet now apply the same delay to every generated coin, measured in time rather than in blocks: the mempool does not relay a spend of a generated coin until the median time past of the chain tip is at least one year (365 days) past that of the block that generated it, and the wallet counts the coin as immature until then. For bitcoins generated since block 973440 this is never sooner than the consensus release, which the mempool also enforces directly, so a wallet holding generated bitcoins can no longer select coins that the network would not accept. The number of blocks to maturity shown for such coins is an estimate, updated with every block.

`getdeploymentinfo` reports the release time as `expiry_time` for `long_coinbase_maturity`, and no longer reports `height_end` or `maturity` for it. The regtest option `-testcoinbasematuritylong` now takes `<start_height>:<enforce_height>:<release_time>`.
